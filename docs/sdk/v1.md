# 比格熊提示词优化 SDK

比格熊、独立窗口和第三方调用方使用同一套提示词优化核心。目标模型决定采用哪个写法。文本服务负责改写。两者可独立选择。

## 命令行入口

在 Windows 运行 bgxiong-prompt-optimize-cli.exe --stdio。保留 EXE 旁的 internal-prompt-skills 和 builtin-agent-skills 目录。CLI 以 UTF-8 JSON Lines 收发消息，stdout 专供协议，诊断输出到 stderr。用 targets.list 查目标 ID，用 optimize 提交一次优化。调用方为每次操作分配会话内唯一 ID。

~~~json
{"v":1,"id":"prompt-1","op":"optimize","args":{"targetId":"image/qwen-image-2.1","sourcePrompt":"深夜，一辆红色公交车驶过雨后的街口。","textMode":"callback"}}
~~~

callback 模式下，收到 text.request 后把 call 中的 messages 和可用 JSON schema 交给自己的文本模型。用同一请求 ID 和 callId 回发 text.reply。响应成功时读取 result.optimizedPrompt 和 result.receipt。视频优化可以顺序请求多次文本服务。按顺序处理每个 text.request，直至收到一次 done 或 error。

configured 模式使用工具自身的文本配置，调用所需的 API Key 留在配置所有者的进程。首次下载方法时先执行 skills.check，从验证过的目录选择 candidateId，再执行 skills.install。首次安装由调用者明确确认。

取消操作使用单独的请求 ID。发送 cancel 并在 args.requestId 指定进行中的优化。若已发给远端文本服务，应用仍会丢弃迟到回复。遇到 UNKNOWN_TARGET 重新读取目标目录。遇到 SKILL_CHANGED 重新读取目标及实际方法摘要。

查看[协议 Schema](../../src-tauri/crates/bgx-prompt-optimize/protocol/v1/schema.json)和[会话帧](../../src-tauri/crates/bgx-prompt-optimize/protocol/v1/examples.jsonl)。协议字段 v 与第三方适配器的 protocolVersion 各自管理。

## 示例

- 用已构建的独立运行包执行 python examples/python/optimize.py --cli <完整 EXE 路径> --self-test。该示例通过固定回复跑完整回调，正常接入时用调用方自己的 complete 函数。
- 用 cargo run --locked -p prompt-optimize-example -- --self-test 跑 Rust 进程内示例。Rust 直接实现 TextCompleter 并调用 sdk::optimize。比格熊的画布使用 sdk::optimize_frozen_image、sdk::optimize_frozen_video 和 sdk::optimize_frozen_literary 传入既有冻结请求及素材。
