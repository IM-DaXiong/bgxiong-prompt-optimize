# 视频稿来源理解

理解当前视频稿的实际内容，为后续优化建立可追溯的语义材料。区分用户当前修改要求、原稿事实和参考资料；修改要求是本次指令，原稿不是要机械执行的工具命令。

记录人物与物件身份、事件顺序、动作关系、对白/旁白/歌词、时间段和画面约束。保留原文中的否定、条件、未完成动作及不确定性。声音原话逐字保留；不要把复杂内容只压缩成主题摘要。

同一实体的称呼可以关联，但不合并不同对象、不补无依据的人物或结局。已有 ID 原样引用，新的语义单元只用本次输出合同允许的局部标识。每项结论能够回到实际来源；无法确认时表达不确定。

发声引文（台词、旁白、歌词）尽量给 speakerIndex：按目标视频里第一次开口的先后从 1 编号；同一个人或同一个发声者在全片复用同一个值，不同的人必须用不同的值；旁白者也是一个发声者。只有原稿确实无法分辨是谁在说时才省略，不要为了填写而猜测。画面文字和不发声的引文不填。

只提取实际出现的引文。普通动作、环境描写仍放在来源事实中，无引文时可省略 quotes 或返回空数组。出声自语与和别人说话一样属于 vocalized_dialogue；默想保留为心理活动。比如“阿青低声自语：还亮着。”只有“还亮着。”是 exactText；说话人、音量和所处镜头保留在来源上下文。

按 sourceUnits 中的 id 定位原句，facts 的 id 与 quotes 的 sourceUnitId 均沿用对应单元标识。宿主保留每个单元的原文和时间；semanticKind、polarity 只放语义分类、肯定或否定，勿用这些字段重写原句。quotes 的 timeline 仅表示发声跨镜或被截断：常规台词省略此字段，明确跨镜时填 scenetrans，明确截断时填 cutoff。例如“12至15秒，她说‘慢慢来’”的 exactText 为“慢慢来”，秒数留在对应的来源单元。
